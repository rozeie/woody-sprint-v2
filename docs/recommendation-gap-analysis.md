# 추천 공백 조사 (2026-10-17)

특정 고민 조합에서 추천이 0개가 되는 원인을 기존 데이터로 확인한 기록이다. **추천 규칙은 바꾸지 않았고 관련 없는 자료로 개수를 채우지도 않았다.** 이번에는 자료 20~30개를 일괄 생성하지 않고, 조사 결과를 이후 콘텐츠 보강 우선순위로 남긴다.

- 재현: `node scripts/recommendation-gap.mts`(가상 예시 자료 11개만, 원문 자료 추가 전) 또는 `--catalog`(현재 전체 목록)
- 규칙(`src/lib/content/recommend.ts`): 확정한 주제와 겹치는 자료만 후보, 겹친 수가 많은 순(같으면 목록 순서), 두 번째는 가능하면 첫 번째와 다른 유형, 후보가 2개 미만이면 있는 만큼만. 새 회차(매일 오후 6시)에는 **직전 추천과 이미 선택한 자료를 후보에서 뺀다**(`HomeGate.tsx`).

## 원인 두 가지 구분

| 구분 | 의미 | 이 데이터에서 |
|---|---|---|
| ① 주제 자료 부족 | 확정한 주제에 맞는 자료가 처음부터 없거나 1개뿐이라 1회차부터 0개 또는 1개 | 고민 칩 27개 중 **13개 주제에 자료가 0개**(UX 라이팅, 페르소나와 사용자 여정, 경쟁 서비스 분석, 가설 세우고 검증하기, 사용성 테스트, 접근성 고려, 예외 상황 설계, 디자인 리뷰 진행, 개발 전달 문서, 이력서와 자기소개서, 디자인 과제 전형, 실무 적응, 성장 계획 세우기). 자료가 있는 주제도 대부분 1~3개 |
| ② 회차 소진 | 자료는 있었으나 직전 추천과 선택한 자료를 계속 빼다 보니 이후 회차에서 후보가 바닥남 | 가장 넉넉한 조합도 2회차 뒤 소진. 자료 11개를 하루 2개씩 쓰면 전체로도 최대 5일 |

기존 사용자가 어느 날 추천 0개를 본 경우는 대부분 ②다. 첫날 정상적으로 2개를 받았더라도, 후보가 4개 이하인 조합은 2일 이내에 후보가 모두 제외되어 새 회차에 부족 상태(0개)가 된다. ①인 조합은 첫날부터 0개 또는 1개다. 두 경우 모두 앱은 의도한 대로(관련 없는 자료로 채우지 않고) 부족 상태를 보여 준다.

## 콘텐츠 보강 우선순위 (제안, 자료 제작은 이번 범위 아님)

1. **사용성 테스트** (자료 0개, 대표 조합에서 가장 자주 걸림, 접근성과 함께 쓰이는 조합 포함). 이번에 원문 기반 자료 1개를 만들었다(`docs/content-sources.md`).
2. **접근성 고려** (자료 0개, 같은 빈도). 공개 공식 문서(예: 접근성 표준 문서)가 있어 원문 기반 자료로 만들기 좋다.
3. 자료 0개에 자주 걸린 나머지: 가설 세우고 검증하기, 디자인 과제 전형, 성장 계획 세우기, 실무 적응, UX 라이팅, 예외 상황 설계, 디자인 리뷰 진행.
4. 자료가 1개뿐인 주제(정보구조와 플로우 설계, 인터랙션과 프로토타이핑, 개발자 협업, 디자인 피드백 받기, 면접 준비, 직무 이해와 방향 설정)에 1개씩 더하면 2회차까지 늘어난다.
5. 회차 소진을 줄이려면 주제마다 4개 안팎이 필요하다(하루 2개, 이틀 이상 새 자료). 이 수치는 현재 규칙(직전 추천과 선택 자료 제외)과 하루 2개 추천을 기준으로 한 계산이며, 규칙 자체(D-08)는 미확정이다.

## 이 조사의 한계

- 20개 조합은 그룹별 대표 고민을 섞어 직접 고른 것이며, 실제 사용자 분포가 아니다. 모의 분석이 고민 칩 외의 주제를 덧붙이는 경우(고르지 않은 주제로 채움)는 포함하지 않았다.
- 규칙 완화나 대체 추천(관련 없는 자료로 채우기)은 하지 않았고 효과를 시험하지 않았다.

## 새 회차 재추천 규칙과 원문 자료 4개 후 (2026-10-17)

바뀐 점
- 추천 규칙: 새 회차에서 직전 추천을 완전히 빼던 것을, 이미 선택한 자료만 계속 빼고 직전 추천은 뒤로 미루는 것으로 바꿨다. 직전 추천에 없던 관련 자료를 먼저 쓰고, 신규로 2개를 채우지 못할 때만 직전 추천 중 선택하지 않은 자료로 부족한 수만 보충한다. 추천 수(2개), 관련 없는 자료로 채우지 않는 원칙, 회차당 선택 1개는 그대로다.
- 자료: 원문 기반 자료를 UX 라이팅 2개(NN/g 오류 메시지 가이드라인, HSE 입력 오류 문구 가이드), 개발자 협업과 개발 전달 문서 1개(Figma 핸드오프 핸드북)로 3개 늘려 4개가 됐다(`docs/content-sources.md`).

검사 방법: `node scripts/recommendation-gap.mts`가 대표 조합 20개(단일 주제 5개와 복수 주제 15개, UX 라이팅과 개발자 협업 포함, 전체 주제군에 분산)에 현재 자료와 현재 규칙을 적용한다. 가능한 모든 조합을 검사한 것이 아니다. 열의 뜻은 다음과 같다.
- 관련 후보: 확정 주제와 겹치는 전체 자료 수.
- 2회차(선택 없음): 1회차 추천을 선택하지 않았을 때 새 회차의 개수와 그중 신규 자료 수. 보충은 직전 추천을 다시 쓴 개수.
- 2회차(첫 추천 선택): 1회차의 첫 추천을 선택했을 때 새 회차의 개수(선택한 자료는 빠짐).
- 모두 선택한 뒤 빈 상태: 관련 자료를 모두 선택했을 때 홈에 나오는 안내.
- 검사: 추천 결과에 관련 없는 자료, 같은 묶음 중복, 선택한 자료의 재노출이 없는지.
