# Stack UI 데모 — 임시 결정 및 미확정 목록

> 기준: `PRD-v0.2.md`(기능·정책), `DESIGN.md` v0.2.1(시각·상호작용). 이 문서는 PRD를 변경하지 않으며, UI 데모에서 불가피하게 둔 **임시 선택**과 PRD의 **미확정 항목**만 기록한다. 제안은 확정 정책으로 승격하지 않는다.

## B. 구현 결정

| 결정 | 내용 | 비고 |
|---|---|---|
| 새로고침 시 상태 유지 | **유지한다.** 온보딩 입력, 분석 결과와 세부 주제 수정 상태, 확정 값을 localStorage(`stack-demo:v1:*`)에 임시 저장하고 새로고침 시 복원 | 데모 전용. PRD의 서버 DB·익명 세션 복원을 대체하지 않으며, 사이트 데이터를 지우거나 다른 브라우저에서 열면 사라진다 |
| 데이터 접근 계층 | UI는 `StackRepository`(저장)와 `AnalysisService`(분석) 인터페이스만 사용. 현재 구현은 각각 데모 저장소·모의 서비스 | 교체 지점: `src/lib/data/index.ts`, `src/lib/analysis/index.ts` |

| 분석 시작 | 온보딩 제출 → `/onboarding/analyzing`에서 자동 시작. 진행 중에는 시작·재시도가 한 번만 실행 | 화면이 다시 보일 때마다 새로 시작(라우터가 이전 화면을 숨긴 채 유지하기 때문) |

### 3단계 결정

| 결정 | 내용 | 비고 |
|---|---|---|
| 추천 생성 시점 | 확정 직후 2개를 만들어 저장(PRD F1-05 ⑥). 저장된 묶음이 없거나 확정한 주제와 다르면 홈 진입 시 한 번 다시 만든다. 이후에는 같은 묶음을 그대로 보여 준다 | **매일 18:00 KST 교체와 접속 시 주기 판단은 구현하지 않음**(추천은 고정). 홈에 안내 문구 표시 |

### 4단계 결정 (선택 · 모의 서재 · 리더 진입)

| 결정 | 내용 | 비고 |
|---|---|---|
| 선택 위치 | 홈 카드의 "선택하기"와 상세 미리보기의 "이 자료 선택하기". 버튼 바로 아래에 "선택한 학습 자료는 변경할 수 없어요."를 상시 노출 | 선택 확인 모달은 쓰지 않음(PRD 미확정, 상시 안내로 갈음) |
| 선택 제약 | 추천 묶음(세트 id)당 1개. 같은 자료 중복 선택은 기존 기록을 돌려주고, 같은 묶음의 다른 자료 선택은 거절한다. 변경·취소·추가 선택 UI 없음. 선택 후 다른 카드는 비활성 + 이유 문구 | 규칙: `src/lib/selection-rules.ts`. 모의 저장 지연 350ms + 화면의 진행 중 차단(빠른 중복 클릭 1건) |
| 선택 ≠ 시작 ≠ 완료 | 선택은 `selectedAt`만 기록. 리더에 처음 들어올 때 `startedAt`을 한 번 기록(서재 '읽는 중'). `completedAt`은 5단계의 명시적 완료에서만 | 리더 진입·스크롤·시간으로 자동 완료하지 않음 |
| 후보 1개일 때 선택 | 임시로 허용 | PRD D-09 미확정 |
| 서재(최소) | 선택한 자료 목록과 상태(선택함/읽는 중), 학습 시작·이어서 읽기 링크. 삭제 기능 없음, 빈 상태에서 홈 이동 | 회고 확인·완료 표시는 이후 단계. 확정 전에도 URL로 열림(§9.3 확인 필요) |
| 이어서 읽기 | 홈의 오늘의 추천 아래. 완료하지 않은 선택 자료를 최근 순으로. 선택한 자료가 없으면 영역 생략 | 읽던 위치 복원은 P1이라 하지 않음 |
| 리더 진입 | `/read/[id]`. 선택한 자료만 열림(미선택·없는 자료·확정 전은 안내 또는 온보딩 이동). 하단 탐색 숨김, 이전(←) 버튼 | 4단계에서는 본문 자리에 안내만 두었고, **5단계에서 본문과 학습 완료로 대체됨** |

### 가운데 점 사용 금지 (사용자 지시, 5단계 적용)

사용자 지시에 따라 사용자에게 보이는 모든 화면의 문구와 메타데이터에서 가운데 점 문자 `·`와 `ㆍ`, 구분용 `•`를 쓰지 않는다. PRD와 DESIGN 원본은 수정하지 않았고, 이 지시를 구현 코드와 이 기록에 반영한다.

| 적용 | 내용 |
|---|---|
| 구분 방식 | 유형, 주제, 시간은 간격과 별도 요소로 구분(`flex`와 `gap`). 문장에서는 쉼표나 "와", "과" 같은 연결어. 상태 구분은 마침표나 콜론 |
| 목록 | 점 모양 목록 표시(`list-disc` 등)와 CSS가 넣는 구분 문자(`before/after content`)를 쓰지 않는다. 순서나 단계가 있는 목록은 번호 목록(`ol`), 항목 이름이 있는 설명은 정의 목록(`dl`), 짧은 구절 묶음은 `ul`을 쓰되 점 없이(`list-none`) 쉼표로 이어 읽게 한다 |
| 칩 라벨 변경 | PRD F1-01이 "제안"한 칩 이름 중 가운데 점이 있던 이름을 바꿨다(PRD 원본은 그대로): 문제 정의와 리서치(그룹), 데이터 해석과 지표 설정, 정보구조와 플로우 설계, 인터랙션과 프로토타이핑, 직무 이해와 방향 설정, 협업과 소통(그룹). 칩 키는 그대로 | 칩 목록은 원래 PRD D-03 미확정 |

| 접근성 라벨 | `aria-label`, 화면 낭독용 문구, 문서 제목과 메타 설명도 같은 규칙 적용 | |
| 자동 점검 | 단위 테스트: 소스(주석 제외)와 화면에 나가는 모든 데이터에서 금지 문자와 점 목록, CSS 구분 문자를 검사(`tests/no-middle-dot.test.mts`). 브라우저 검증: 모든 화면의 보이는 텍스트, 접근성 속성, 메타 태그, `::before/::after` 내용, 목록 표시 모양을 검사 | 코드 주석과 이 문서는 화면에 나가지 않으므로 대상이 아님 |

## 후속 UI 수정 목록 (지금 전면 수정하지 않음)

사용자 요청으로 기록만 한다. 4단계에서는 현재 UI를 유지했다.

1. **학습 스택(잔디) 그래픽 확대** — 현재 칸이 작다(390px에서 약 18px). 날짜별 목록과 설명이 차지하는 공간과 함께 재조정.
2. **밝고 선명한 브랜드 그린 사용 재검토** — 기본 CTA·활성 칸 색(`primary` #18C37E)의 사용 범위를 다시 검토. DESIGN §2 "밝은 그린의 넓은 사용은 읽기 집중도를 약화" 항목과 함께 본다.
3. **상세 미리보기의 관련 정보 묶음과 표면 구분** — 5개 항목을 관련 정보끼리 묶고 카드·표면으로 구분.
4. **길게 펼쳐지는 날짜별 목록 제거 및 접근 가능한 대체 표현 유지** — 현재는 토글로 접어 두었지만 펼치면 28줄이 길게 나온다. 긴 목록 없이도 스크린리더·텍스트 사용자가 날짜별 상태를 알 수 있는 대체 표현(요약 문장 등)을 유지하는 방식으로 교체.
